# 项目基础设施设计规范

## 项目概述

本项目旨在构建一个通用的多游戏自动化平台，通过图像识别作为输入，模拟鼠标键盘作为输出，在严格遵守游戏公司ToS的前提下实现自动化操作。

## 核心设计原则

### 1. 文档先行开发方式

**开发流程**：
1. **准备阶段** - 查阅现有文档（docs/、.claude/memory/、.claude/plan/）
2. **设计阶段** - 在文档中记录设计决策和变更计划  
3. **实现阶段** - 按文档进行代码实现
4. **验证阶段** - 实现后review并更新所有相关文档

**文档体系**：
- `.claude/memory/` - 开发过程记录和技术决策
- `docs/` - 正式需求、架构、API文档  
- `.claude/plan/` - 实施计划和任务分解
- 各目录 `README.md` - 目录结构和使用规范

### 2. 文档架构设计

- `requirements.md` - 功能需求和合规要求

### 3. CLAUDE.md 增强规则

**强制文档加载规则**：
- 每次会话启动必须读取 `docs/` 下所有 `.md` 文件
- 必须读取关键目录的 `README.md` 
- 必须加载 `.claude/memory/` 下的所有历史记录

**文档维护规则**：
- 任何代码变更前必须先查阅和更新相关文档
- 实现完成后必须review文档确保同步
- 新增目录必须同时创建标准 `README.md`
- 设计决策必须记录到对应文档中

### 4. 合规要求架构

**核心约束**：
- 仅使用图像识别（截图分析）作为输入
- 仅使用鼠标键盘模拟作为输出  
- 禁止网络抓包或协议分析
- 完全基于"看屏幕+点击操作"的人类行为模拟

**技术选型**：
- 图像识别：OpenCV模板匹配 + PaddleOCR文字识别
- 输入模拟：Win32 PostMessage（后台）+ pydirectinput（前台备选）
- 任务编排：JSON声明式管线 + Python类（复杂逻辑）
- GUI界面：PySide6 + Fluent Design
