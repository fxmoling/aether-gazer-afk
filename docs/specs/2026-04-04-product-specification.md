# 产品规格

## 产品定位

深度自动化游戏助手。先深度支持一款游戏（深空之眼），建立完整技术栈，再扩展为多游戏平台。

**合规约束**（不可违反）：
- 只通过截图做图像识别，只通过模拟鼠标键盘做输入
- 不解析/发送网络请求，不做抓包/协议分析
- 不修改游戏内存/文件

## 三大核心能力

### 1. 完全后台运行（核心，Phase 1 必须）

用户启动任务后可以正常使用电脑。游戏窗口可以在后台、最小化、被遮挡。

- 不出现可见的鼠标移动
- 不抢夺焦点
- 不影响用户当前操作

### 2. 定时任务（Phase 2）

支持设定时间自动执行任务。

- 集成 Windows 任务计划程序
- 支持电脑自动唤醒执行
- 虚拟显示器支持（无显示器/远程桌面场景）

### 3. 跨游戏编排（Phase 3）

支持多个游戏的任务串联。

- 例：深空之眼日常 → 另一游戏日常 → 关机
- 游戏间自动切换（关闭A、启动B）
- 单个游戏失败不影响后续游戏

## 初始游戏：深空之眼

### 优先功能

**A. 日常任务自动化**
- 自动登录 / 领取签到奖励
- 一键完成每日任务流程
- 体力消耗（自动选关、战斗、领奖）
- 弹窗处理（体力不足 → 按用户配置使用体力药）

**B. 主线/关卡推进**
- 导航到主线剧情页面
- 识别下一个待完成关卡
- 选择角色阵容（用户预配置）
- 进入关卡 → 战斗 → 领取奖励

### 场景复杂度分析

| 场景 | 复杂度 | 实现方式 |
|------|--------|----------|
| 菜单导航、点击按钮、领奖励 | 低 | JSON 管线 |
| 关卡选择、体力判断、角色配置 | 中 | 条件 JSON + 参数注入 |
| 实时战斗（闪避、技能循环、切人） | 高 | Python 战斗引擎 |
| 地图导航（走到交互点、交互） | 高 | Python 导航引擎 |
| 弹窗打断恢复 | 中 | JumpBack 机制 |
| 剧情跳过、CG 跳过 | 低 | JSON 管线 |

### 任务编排架构

三层，按复杂度选用：

```
Layer 1: JSON 声明式管线
  — 固定流程：菜单导航、领奖励、跳过剧情
  — MaaFramework 原生支持
  — 非程序员可编辑

Layer 2: 条件 JSON 管线
  — 带分支的流程：关卡选择、体力判断
  — 支持 OCR 读取 + 条件跳转
  — 参数化（用户配置注入）

Layer 3: Python 脚本
  — 复杂编排：调用战斗引擎、导航引擎
  — 完整编程能力
  — 用户可自定义
```

### 专用引擎（Layer 3 调用）

**战斗引擎** — 深空之眼是 3D 动作游戏，战斗不可能用 JSON 管线

需要处理：
- 技能释放循环（检测 CD → 释放）
- 闪避判断（检测敌人攻击前摇 → 闪避）
- 角色切换
- 血量监控 → 使用回复道具
- 参考：ok-wuthering-waves 的 BaseCombatTask + CharFactory

**导航引擎** — 地图内移动到指定位置

需要处理：
- 当前位置检测（小地图分析）
- 方向计算 → WASD 持续按键
- 到达判定
- 交互点识别与交互
- 参考：BetterGI 的 Pathing 系统

## 技术路线

- **核心引擎**: MaaFramework（LGPL-3.0，动态链接，无协议风险）
- **应用层**: Python 3.11+
- **编码规范**: 见 `docs/coding-standards.md`

### 依赖关系

```
Python 应用层
  ├── GUI (PySide6)
  ├── 任务编排 (JSON 管线 + Python 脚本)
  ├── 游戏适配 (深空之眼适配器)
  ├── 定时任务 (Windows Task Scheduler)
  └── 跨游戏编排
          ↓
MaaFramework Python 绑定
          ↓
MaaFramework C++ 核心
  ├── 图像识别 (模板匹配, OCR, 特征匹配)
  ├── 输入模拟 (PostMessage 后台)
  ├── 截图 (DXGI / BitBlt / GDI)
  └── 任务管线引擎
          ↓
Win32 API / 系统
```

## 开发阶段

### Phase 1: 后台运行 + 深空之眼基础（核心）

目标：深空之眼能在后台完成日常任务

交付：
- MaaFramework 集成，后台截图 + 后台输入验证
- 深空之眼窗口识别与管理
- 日常任务 JSON 管线（登录、签到、领奖）
- 基础战斗引擎原型
- 体力消耗自动化

成功标准：
- 游戏最小化状态下稳定运行
- 日常任务完成率 > 90%

### Phase 2: 定时任务 + 深度功能

目标：无人值守定时执行，更多游戏功能

交付：
- Windows 定时任务集成
- 虚拟显示器支持
- 主线关卡推进
- 战斗引擎完善（多角色、多关卡类型）
- 导航引擎

### Phase 3: 多游戏平台

目标：支持第二款游戏，形成通用框架

交付：
- 游戏适配器抽象层
- 第二款游戏适配
- 跨游戏工作流引擎
- 用户配置界面
