# UI 映射开发范式 (2026-04-04, updated 2026-04-05)

## 核心思想

游戏自动化的本质是 **页面导航 + 元素交互**。在写任何自动化脚本之前，必须先建立一套完整的、结构化的 UI 地图。

## 五层递进架构

```
Layer 1: 页面截图 + 元素标注 (Page Map) — 部分完成，需重新验证
    → docs/pages/aether_gazer/ 16个页面文档（坐标需重新验证）
    ↓
Layer 2: 单元素交互 (Element Action)
    → pages/definitions.py (InteractiveElement, NavAction) — 坐标需更新
    ↓
Layer 3: 基础场景 (Basic Scenario)
    → nav/navigator.py (Navigator.navigate_to, ensure_hub)
    → tasks/atomic.py (NavigateToPage, ClickAt, PressKey, etc.)
    ↓
Layer 4: 完整任务 (Complete Task)
    → tasks/daily.py (DailyCheckin, CollectMail, FullDailyRoutine, etc.)
    ↓
Layer 5: 用户工作流 (User Workflow)
    → tasks/base.py (TaskSequence)
    → scripts/run_daily.py
```

## 坐标验证方法论 (2026-04-05 建立)

**旧方法（不可信）**: 像素亮度扫描 → 推算坐标中心 → 直接写入代码
**新方法（交互式验证）**: 截图 → 像素分析定位 → 裁剪区域确认元素 → 精确点击 → 截图验证结果

### 重要发现

1. **Hub 角色模型 hitbox**: 3D角色在Hub中心有可点击hitbox，大约 x=650-930 范围
   - 点击该区域会进入**宿舍大厅**(dormitory)，而不是底部导航栏
   - 解决方案: 导航栏按钮尽量点击靠右侧位置，避开角色覆盖区
2. **Enter键确认对话框**: 某些弹窗（如宿舍退出确认）的橙色按钮点击不生效，但 Enter键 (VK_RETURN=0x0D) 可靠确认
3. **宿舍大厅**: 之前未映射的页面，可从Hub点击角色模型进入
4. **两个返回按钮（通用规则）**:
   - **三角 ◀ (35, 35)** — 返回上一页（栈式：从哪来回哪去）
   - **圆形 ⊙ (112, 35)** — 直接返回 hub
   - 这是所有子页面的通用规则
5. **补给区是充值页面**: shop → 补给区全是真钱商品，标记为禁止操作

### 输入方法 (2026-04-06 实测)

| 方法 | 用途 | 抢光标? | 有效? |
|------|------|---------|-------|
| PostMessageWithWindowPos | 鼠标点击 | ❌ 不抢 | ✅ 页面内有效，但**无法唤醒 hub idle** |
| SendMessageWithCursorPos | 键盘 | ⚠️ 瞬间闪 | ✅ 键盘+唤醒 idle 均有效 |
| SendMessage | 键盘/鼠标 | ❌ | ❌ Unity 不响应 |
| PostMessage | 键盘/鼠标 | ❌ | ❌ Unity 不响应 |

**当前配置**: mouse=PostMessageWithWindowPos, keyboard=SendMessageWithCursorPos
**WakeHubUiOp**: 先按 ESC（唤醒idle），再检测"退出游戏"弹窗，如有则ESC取消

### Hub ESC 行为
| 状态 | ESC 效果 |
|------|----------|
| Hub idle | 唤醒 UI ✅ |
| Hub active | 弹出"是否退出游戏?" ⚠️ |
| 补给区页面 | 返回上级 |
| 弹窗/叠加层 | 关闭 |

## 分辨率注意事项

**当前所有坐标基于 1600x900 分辨率**
- session.py 使用 `set_screenshot_use_raw_size(True)`
- MaaFw 的 post_click 会根据 controller.resolution 做坐标映射
- 如果游戏窗口分辨率不是 1600x900，坐标可能需要按比例缩放

### 联防协议 (Joint Defense) 战斗面板 ✅ (2026-04-06 像素级验证)

5个按钮布局: `<<` `<` [xN] `>` `>>`

| 元素 | 坐标 | 验证方法 |
|------|------|----------|
| 掉落倍数 xN 文字 | center (1351, 716) | OCR |
| > (单步+1) | center (1490, 712) | 像素扫描 |
| >> (最大倍数) | center **(1552, 712)** | 像素扫描 ✅ 实测 x1→x6 |
| < (单步-1) | center ~(1210, 712) | 推测 (x2+时出现) |
| << (最小倍数) | center ~(1150, 712) | 推测 (x2+时出现) |
| 扫荡 | center (1252, 841) | OCR |
| 作战 | center (1466, 841) | OCR |

**重要**: `>` 和 `>>` 按钮是暗色箭头图标，OCR 无法识别，必须用像素映射。
x1 时只显示 `>` 和 `>>`；x2+ 时所有5个按钮都显示。
