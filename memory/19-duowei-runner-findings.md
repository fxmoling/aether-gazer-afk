# 多维变量自动化 — 发现与结论 (2026-04-23)

## 一、核心成果

实现了完整的多维变量 Process + Task，E2E 验证通过，可无限循环获取积分。

- **DuoweiProcess** (`processes/duowei_process.py`) — 无限循环 Process
- **DuoweiCombat** (`tasks/duowei_tasks.py`) — 单次挑战 Task
- **duowei_runner.py** (`scripts/`) — 命令行测试工具 (`--loop` / `--resume`)

---

## 二、策略：最小循环

只通关 1-2 层即退出，获取最低限度积分（~10万+/次）。

```
导航到多维变量页 → 开始挑战 → Setup(赏金猎人信标) → Loading
→ 1-1 珍宝选择(确认) → swipe旋转 + W前进 + J交互(进入传送门) → Loading
→ 1-2 战斗(攻击循环) → 奖励处理(中央+确认) → ESC+H+Enter退出结算
→ 回到多维变量页 → 重复
```

---

| 参数 | 值 | 说明 |

| 攻击循环 | J J U J I J O R 1 2 | 0.12s间隔，5循环≈10s |

## 四、导航流程

1. OCR检测"记忆珍宝图鉴" → 已在多维变量详情页 → 直接点开始挑战
2. 否则: ReturnToHub → 按J进入战斗页 → 点击挑战tab(0.83,0.9)
3. 挑战列表: OCR找"多维变量"(取y最大的匹配=卡片图标)
4. 找不到则点击左侧(0.05,0.5)滚动列表，最多3次
5. 进入详情页后: OCR点击"开始挑战"/"继续挑战"

- 角色页: OCR点击"下一步"  
- 信标页: swipe下滑2次 → OCR找"赏金猎人"并点击 → OCR点击"开始挑战"

## 六、MaaFramework 输入特性

- `hold_key` = PostMessage快速按放循环(100ms间隔)，非真正KeyHold
- `swipe()` = post_swipe，用于相机旋转（距离可控、速度无关）
- `press_key` = 单次PostMessage按放
- 所有操作均为后台操作，游戏窗口无需前台

---

## 七、错误恢复

- 单次失败: 尝试ESC+H退出 → 继续下一轮
- 连续3次失败: 停止Process并报告
- 未知状态: ESC spam作为最后手段

## 八、战斗按键配置

战斗按键可在 设置 → 战斗按键 中自定义，存储在 `user_config.json` 的 `combat_keybinds` 字段。

| 功能 | 默认键 | 配置key |
|------|--------|---------|
| 攻击 | J | attack |
| 技能1 | U | skill1 |
| 技能2 | I | skill2 |
| 技能3 | O | skill3 |
| 大招 | R | ultimate |
| 闪避 | Space | dodge |

- `DuoweiCombat.__init__()` 从 UserConfig 读取，通过 `letter_to_vk()` 转换
- 攻击循环: attack×2 → skill1 → attack → skill2 → attack → skill3 → ultimate → QTE1 → QTE2
- QTE (1, 2) 不可配置，保持默认

## 十、强制选角 真红 (2026-05-11)

### 背景
默认让游戏自动选第一个角色，可能太弱打不过 1-2。**真红** 是所有玩家都拥有的角色，且符合 `真樱 + 物理` 两个 tag 的筛选条件。

### 流程
角色页 (`_complete_setup` Step 2) 新增子流程 `_select_force_character`：

1. **打开筛选** — 直接点 fallback 坐标（漏斗按钮无文字标签，OCR 无法定位）
2. **筛选 tag** — OCR 找 `真樱`、`物理` 并依次点击
3. **确认筛选** — OCR `确认` / `确定`，找不到则 Enter
4. **乐观判断** — 筛选完 OCR 检查 `真红` 是否已在右侧预览
5. **遍历头像网格** — 按 `cols × rows`（默认 2×4）顺序点击，每次 OCR 验证 `真红`
6. **安全保护** — 任何时刻 `下一步` 消失 → 说明误点了导航按钮 → 中止扫描

### E2E 验证结果 (2026-05-11)

实测数据（1600×900 截图，`actual_resolution=1600x900`）：

| 元素 | px | frac | 验证 |
|------|----|------|------|
| 漏斗筛选按钮 | (64, 838) | **(0.040, 0.931)** | ✅ click 后 dialog 打开 |
| `真樱` tag | (104, 155) | (0.065, 0.172) | ✅ OCR 找到并点击 |
| `物理` tag | (136, 341) | (0.085, 0.379) | ✅ OCR 找到并点击 |
| `确认` 按钮 | (255, 824) | (0.159, 0.916) | ✅ OCR 找到并点击 |
| 头像 1 中心 | (~202, ~222) | **(0.126, 0.247)** | 等级80标签上方 80px |
| 头像列间距 | (418-167) | **0.157** | 横向 |
| 头像行间距 | (474-302) | **0.191** | 纵向 |

**关键发现**：
- 漏斗按钮**无文字标签**，OCR 永远找不到 `筛选`，必须直接走 fallback
- 实测账号：真樱+物理 筛选后**只剩 1 个角色** = 真红，乐观判断（OCR `真红`）直接命中，无需遍历头像
- **战力变化**：震离 21285 → 真红 19960（确认切换成功）

### 配置项 (UserConfig)

| 键 | 默认值（已校准） | 说明 |
|----|-----------------|------|
| `duowei_force_character` | `"真红"` | 角色名；空字符串关闭整个流程 |
| `duowei_filter_tags` | `["真樱", "物理"]` | tag 列表 |
| `duowei_avatar_grid` | `{x1:0.126, y1:0.247, offset_x:0.157, offset_y:0.191, cols:2, rows:4}` | 头像网格（fractional） |
| `duowei_filter_button_fallback` | `[0.040, 0.931]` | 筛选漏斗按钮坐标 |

### 失败行为
任何步骤失败 → log warning → **保留游戏当前选中的角色** → 继续点 `下一步`。
绝不抛异常打断 setup 流程。

### 已知敏感性
- 不同账号"真樱+物理"组合可能 1-N 个角色，乐观判断不命中时 fallback 到头像遍历
- 不同分辨率下 tag 文字位置浮动小（OCR 不受影响），但漏斗 fallback 坐标可能需要在 4:3 / 21:9 屏幕上微调
- 用户可在 `config/user_config.yaml` 直接覆盖任何坐标
